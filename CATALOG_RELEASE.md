# Каталог SkyVision

## Что изменено

- Главная ведёт к сравнению заводов и объясняет путь от выбора продукции к заявке.
- 15 заводов из старого каталога восстановлены в `sv_catalog` и `sv_catalog_drafts`.
  Сохранены 13 реально существующих файлов. Неработающие ссылки не перенесены.
- Старые цены и условия сохранены в поле provenance для сверки. Публичные цены
  оставлены по запросу: сведения из истории Git не подтверждают текущую стоимость.
- У каждого завода несколько товаров, отдельные маршруты и тарифы в USD/т.
  DAP считается только при наличии FCA, названия пункта и тарифа.
- Редактор: информация RU/ZH, продукция, доставка, фото/видео, документы,
  обложка и порядок, несколько файлов за загрузку, сжатие фото до 1920 px,
  предпросмотр RU/ZH, черновик, публикация, скрытие, корзина, восстановление.
- Черновики физически отделены от публичных карточек. Сохранение и публикация
  атомарны, версия предотвращает перезапись изменений из другой вкладки.
- Права нового каталога основаны на защищённом списке sv_catalog_admins.
- Файлы хранятся в отдельном закрытом bucket. Посетителю доступны только файлы,
  на которые ссылаются опубликованные карточки. Подписанная ссылка живёт 1 час.
- Заявки используют прежние EmailJS service/template/public key и WhatsApp.
  Передаются выбранные завод, товар, город, направление и объём.

## Уже применено к базе

`database/catalog.sql`, `database/restore.sql` и `database/legacy-access.sql` применены к проекту
`wozpvwahlgrdeyypomfx`. Первый файл не повторяемый: не запускать повторно.
Существующие таблицы и заводы не удалены и не изменены. Новый интерфейс использует
новые таблицы, поэтому экспериментальные записи прежнего редактора не отображаются.

## Проверки

- Production build с CI=true; тесты расчёта DAP, валидации, дат цены, URL и главной.
- SQL-проверки с rollback: черновик, публикация, непубличные изменения, корзина,
  восстановление; неадминистратор не видит черновики и не может вызвать сохранение.
- `tools/ui-check.cjs` проверяет браузер, мобильный экран и языки; переменные
  SKYVISION_TEST_EMAIL/PASSWORD включают проверку входа и редактора.
  Скрипт не отправляет писем и не меняет опубликованные карточки.

## Перед публикацией

- Уточнить действующие FCA и тарифы по пунктам назначения, затем заполнить редактор.
- Автоперевод новых текстов не подключён: нет выбранного сервиса/API. Переводы
  вводятся вручную; существующие карточки содержат RU/ZH. Пустой перевод показывает RU.
- Отправка реального письма не выполнялась; нужно проверить доставку в Gmail и
  разрешённые домены в EmailJS. Параметры прежней интеграции сохранены.
- В старых таблицах admins и factory_documents включена RLS с политиками доступа.
  Убрано право обычного пользователя менять роль в собственном профиле. Проверено:
  role нельзя обновлять, display_name по-прежнему доступен для изменения.

## Сборка и откат

Используйте pnpm 11.19.0 и pnpm-lock.yaml. `.npmrc` задаёт совместимое с CRA
расположение зависимостей и отключает lifecycle scripts. Нужны прежние публичные
REACT_APP_SUPABASE_URL / REACT_APP_SUPABASE_ANON_KEY из настроек Vercel.
Для локальной проверки: pnpm install, pnpm test --watchAll=false --runInBand,
pnpm build, node tools/preview.cjs. `.env.local` не коммитится.

Откат интерфейса: вернуть предыдущий Vercel deployment. Старые таблицы сохранены.
Новые таблицы при откате не удалять: в них могут быть новые пользовательские данные.
